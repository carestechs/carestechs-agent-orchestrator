# Implementation Plan: T-282 — `work_items.body_md` + `body_sha256` columns (forward-only migration)

## Task Reference
- **Task ID:** T-282
- **Type:** Database
- **Workflow:** standard
- **Complexity:** S
- **Rationale:** AC-1, AC-3, AC-7 — every other task in this FEAT reads from or writes to these two columns. Lands first so the registration service has a place to write.

## Overview
Add `body_md TEXT NULL` and `body_sha256 TEXT NULL` to `work_items`, plus a CHECK constraint on the sha256 format. Forward-only Alembic migration. Both columns are nullable so pre-FEAT-014 rows continue to work during the deprecation window.

## Implementation Steps

### Step 1: Extend the `WorkItem` SQLAlchemy model
**File:** `src/app/modules/ai/models.py`
**Action:** Modify
After the existing `source_path` column (~line 282), insert:
```python
body_md: Mapped[str | None] = mapped_column(Text, nullable=True)
body_sha256: Mapped[str | None] = mapped_column(Text, nullable=True)
```
In `__table_args__`, append a `CheckConstraint`:
```python
CheckConstraint(
    "body_sha256 IS NULL OR body_sha256 ~ '^[0-9a-f]{64}$'",
    name="ck_work_items_body_sha256_format",
),
```
Follow CLAUDE.md naming: snake_case columns, `ck_` prefix on check constraints.

## Edge Cases & Risks
- **Existing rows have NULL body.** Expected. T-288's deprecation shim backfills these from disk on first run; T-290's `import-work-items` backfills the rest in bulk. No DEFAULT, no backfill in this migration.
- **CHECK constraint syntax differs across Postgres versions.** The `~` regex operator is Postgres-specific but stable across 12+. Confirmed Postgres 16+ is the project target (CLAUDE.md tech stack).
- **Autogenerate may emit a `server_default` that wasn't requested.** Manually verify no `server_default` appears on either column — content is required to be supplied at insert time (or left NULL).
